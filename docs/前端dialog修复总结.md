# 前端 Dialog 近期 Bug 修复总结

本文记录 2026-07-30 至 2026-08-10 前端 dialog 相关的主要修复，重点说明“江湖”分隔 dialog 数据修复，以及该修复后暴露出的后续问题。

## 一、江湖分隔 dialog 数据链路

### 1. 江湖详情串页（2026-07-30，`51a97b1a`）

江湖页面（门派战、家族战、区域等）收到详情包时，旧实现直接调用当前选中项的 `onDetail`。当用户快速切换条目、或服务端延迟返回上一条详情时，旧数据会覆盖当前条目，表现为详情内容错位、残留。

修复包括：

- 只有当 `Dialog.jh.selected_item === this` 且返回的 `index` 与当前条目一致时，才刷新右侧详情。
- `desc` 数据按 `data.t` 映射到对应类型（`fb`/`fam`/`ar`）的 dialog，不再依赖当前选中项；即使当前页面已切换，也不会把分隔页数据写入错误对象。
- `desc !== undefined` 替代真假判断，兼容空描述和仅携带索引的响应。

### 2. 按页面隔离响应数据（2026-08-01，`b91e8888`）

江湖问题反映出更普遍的竞态：多个 dialog 共用消息入口，非当前页面的响应可能直接调用 `onData`，覆盖当前页面状态。此次引入 `Dialog.dataCache`，按 dialog 名称缓存后台响应，并在页面重新打开时 `flushData` 重放；关闭包不会缓存，避免重新打开页面后被旧 close 包立即关闭。

同时增加了页面级策略：

- 消息、活动页在后台仍处理增量状态（未读数/徽章），完整列表响应留在缓存中。
- 任务页允许在列表尚未初始化时暂存增量更新，列表到达后合并，且支持新增任务项。
- 背包、帮派等需要实时接收的页面显式声明 `receiveInBackground`。

### 3. `cha id` 后江湖 dialog 被误关闭（2026-08-02，`760d7c1d`）

数据隔离和缓存使 `cha <target>` 响应可能在 master dialog 已经打开时再次进入 `onData`。旧代码无条件 `Dialog.show("master")`，而 `Dialog.show` 对当前页面是切换/关闭语义，于是出现“收到数据后窗口不显示（或刚打开就关闭）”。

修复为仅在 master 不是当前页面时调用 `Dialog.show`，避免重复响应触发 toggle close。

### 4. 隐藏页面快照与江湖首次恢复（2026-08-02，`40879619`）

仅缓存增量仍会造成用户重新打开江湖时先看到旧列表或空白。基础层增加 `cacheWhenHidden`、`hasCachedSnapshot`、`showCached`：识别包含完整 `fbs/families/areas` 的快照后，先恢复页面，再发送必要的锁定请求；江湖页面保持原选中项，避免每次重开都回到初始状态。技能、属性页面也采用同一快照机制。

## 二、由数据隔离引发的后续 Dialog 回归

### 消息子页刷新（2026-08-02，`0424db80`）

消息 dialog 的公告/活动/系统消息是嵌套子页。引入按页面缓存后，子页响应被误判为“非当前页面”，导致选中的子页不刷新。基础层将 `message.selectedChildName` 纳入当前页面判断；切换子页时记录名称并立即 `flushData(childName)`，确保缓存响应在进入子页时消费。

### 消息与技能选择状态残留（2026-08-03，`5d4c22d0`、`41463c35`）

子 dialog 关闭时没有完整清理引用，重新打开消息页可能保留上次子页；技能页关闭后也会保留选中的技能分组，且通用 `.hide` 样式未覆盖技能条目，导致列表显示错误。

修复为：

- 消息页关闭时调用子页 `inner_close`，清空 `selectedChild`/`selectedChildName`；切换时只关闭旧子页，不误删当前页。
- 技能页关闭重置 `selected_item`、技能元素 ID 和 CSS 状态；补充 `.dialog-skills > .skill-item.hide { display: none; }`，恢复分组隔离。

- `203becc7`（2026-08-02）：增加 dialog 菜单布局策略，统一处理按钮排列、字号变化和重排。

- `409fc92c`（2026-08-10）：统一 dialog 底部按钮分隔线，改用伪元素垂直居中绘制，避免字体/高度变化时边线偏移。
- `6c3ad962`（2026-08-02）：修正 dialog 货币标签居中。

## 四、修复后的数据流约束

当前 dialog 数据处理遵循以下顺序：

1. 先按 dialog 名称和子页名称判断响应归属，再决定直接处理、后台处理或缓存。
2. 详情包必须携带可校验的类型/索引；江湖详情只更新仍处于选中状态的条目。
3. 缓存只保存可重放的数据，不保存 close 包；完整快照优先于增量更新。
4. 页面关闭时清理子页引用和选择状态，重新打开时通过 `showCached`/`flushData` 恢复。
5. 布局设置变化后统一触发 footer 溢出检测和菜单重排，避免数据修复带来的 UI 回归。

## 五、回归检查建议

- 江湖：快速切换门派战/家族战/区域并连续请求详情，确认返回顺序打乱时右侧内容仍与选中项一致；关闭后重开，确认快照和选中项恢复。
- 消息：在公告、活动、系统消息之间切换，后台收到列表和增量包时确认当前子页及时刷新，关闭重开不残留子页。
- 技能/属性：切换分组或详情页后关闭重开，确认选择状态、隐藏条目和数据快照正确。
- 菜单/footer：改变字号、dialog 大小和菜单大小，在窄屏下检查按钮溢出、关闭后菜单恢复及分隔线居中。
