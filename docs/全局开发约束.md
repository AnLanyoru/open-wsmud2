# 全局开发约束

> **面向所有 open-wsmud2 开发者。** 以下约束适用于本项目所有实体类型（ROOM、NPC、TASK、USERTASK、AREA、FAMILY、SKILL、OBJ）的编写。各实体编写指南是对以下原则的具体化补充，编写时应同时遵守本文件和各实体编写指南。

---


## 绝对准则、不要随意触碰git相关文件变更操作

对于会导致git历史发生改变，或会导致本地更改取消的操作，除非我允许或我让你执行，git指令仅允许执行：暂存，提交，推送，拉取

## 项目基调：高复用与接口化

> **强制约束**：实现功能前必须先查找并复用项目已有的公共函数、基类方法和专用接口。可跨资源复用、表达引擎规则或统一管理状态的逻辑，不得散落在资源文件中重复实现。

1. **先检索、后实现：** 编写新逻辑前，必须检查核心类、工具模块、相邻资源和项目文档中是否已有对应能力。已有接口能够完成需求时，必须直接复用，不得另写一套近似实现。

2. **单一职责与单一实现：** 同一查找、转换、校验、状态定位或生命周期逻辑只能有一个权威实现。上层接口应调用下层公共函数，不得复制其内部步骤。

   ```typescript
   query_state(id: string): ROOM | undefined {
       return this.query_entry(id)?.query_copy(id);
   }

   read_state(id: string, key: string, def: unknown): unknown {
       return this.query_state(id)?.query_temp(key, def);
   }
   ```

3. **通用逻辑不得定义在资源文件：** `server/res/` 仅承载具体地图、NPC、物品、任务和剧情配置。满足以下任一条件的逻辑，应下沉到对应核心类或公共工具模块：
   - 被两个及以上资源使用；
   - 与具体资源名称、文案和剧情无关；
   - 负责 owner、实例、缓存、持久化、生命周期或容器管理；
   - 需要全项目保持一致行为；
   - 预计后续资源会继续复用。

4. **优先扩展所属领域接口：** 能明确归属于 ROOM、AREA、USER、NPC、OBJ 等领域对象的能力，应实现为对应核心类的公共方法；只有不属于任何领域对象的纯逻辑，才放入通用工具模块。不得为了局部调用方便，在资源文件中创建通用级别的辅助函数。

5. **专用接口优先于底层操作：** 项目已提供专用接口时，调用方不得绕过接口直接操作底层容器、temp、owner、克隆表或持久化结构。专用接口负责封装不变量、隔离规则和清理契约。

6. **修正公共根因而非堆叠补丁：** 如果多个调用点重复出现相同判断或同一种错误，应修正或补充公共接口，再让调用方统一复用。不得在每个资源文件中分别增加临时修补逻辑。

7. **接口设计要求：** 公共接口必须具有明确的参数、返回值、默认值、作用域和失败行为；命名应表达业务语义而非实现细节。新增或修改公共接口时，必须同步更新相关项目指南，并验证现有调用方兼容性。

8. **资源文件允许保留的逻辑：** 与单个资源强绑定的剧情分支、文案、数值配置、房间机关顺序和一次性事件编排可以留在资源文件中；一旦其中出现可独立复用的机制，应立即抽取到公共接口。

## 九、交互消息与命令按钮

运行时需要向玩家提供“按钮+说明文本”时，必须调用 `USER.send_cmd_and_text(...CmdAndText)`，由公共接口生成客户端命令列表。只有按钮标题而没有说明文本时可使用 `send_commands`。房间描述、场景介绍和其他静态 HTML 内容中的链接才使用字面量 `<span cmd="...">...</span>`；技能提示、状态通知和命令回调中禁止手写 `span cmd`。完整参数、换行、分组和类型转换规范见 [消息交互接口使用规范](消息交互接口使用规范.md)。

## 一、类型标注准则

> 编写任何代码时，必须遵循以下类型标注规则。

1. **对象类型属性必须显式标注类型。** 当类属性值为对象字面量（`{...}`）时，必须标注类型：
   ```typescript
   // ✅ 正确
   prop: PropMap = { gj: 10, fy: 5 };
   condition: LearnCondition = {
       skill: { sword: 100 },
       str: 30,
   };
   exits: Record<string, string> = {
       east: "yz/beidajie2",
       west: "yz/wumiao",
   };

   // ❌ 错误：缺少类型标注或使用 as Record<string, ...>
   prop = { gj: 10, fy: 5 };
   exits = { east: "yz/beidajie2" };
   prop = { gj: 10 } as Record<string, unknown>;
   ```
   如果没有现成类型可以使用，询问开发者来创建新的类型。

2. **重写方法（回调钩子）必须显式标注参数类型和返回类型：**
   ```typescript
   // ✅ 正确
   on_enter(me: CHARACTER): void {
       me.notify("欢迎来到" + this.name);
   }
   on_leave(me: CHARACTER, dir: string): boolean | void {
       if (dir === "up") return me.notify_fail("必须先打败守卫。");
   }
   on_heart_beat(dt: number): void {
       for (const item of this.items) { /* ... */ }
   }

   // ❌ 错误：缺少参数类型和返回类型
   on_enter(me) { me.notify("欢迎"); }
   on_leave(me, dir) { return false; }
   ```

3. **`add_action` / `set_item` 的回调函数必须标注参数类型：**
   ```typescript
   // ✅ 正确
   this.add_action("diao", "钓鱼", (me: CHARACTER): void => {
       WORLD.COMMANDS.get('diaoyu')?.enter(me);
   });
   this.add_action("say", "", function(me: CHARACTER, par?: string): void {
       // 处理逻辑
   });

   // ❌ 错误：缺少参数类型
   this.add_action("diao", "钓鱼", (me) => { /* ... */ });
   ```

4. **存储类字典必须使用无原型对象：** 键来自命令、路径、存档、网络输入或运行时注册的数据映射，必须使用 `Object.create(null)` 创建，避免 `constructor`、`toString`、`__proto__` 等继承属性误命中：
   ```typescript
   // ✅ 正确：动态构建字典
   const cache: Record<string, ItemData> = Object.create(null);
   cache[key] = value;

   // ✅ 正确：带初始值的只读配置字典
   const groups: Record<string, string[]> = Object.assign(Object.create(null), {
       smith: ['sword', 'blade'],
   });

   // ❌ 错误：将普通对象用作不受控字符串键的存储字典
   const cache: Record<string, ItemData> = {};
   cache[key] = value;
   ```
   固定字段的数据对象、JSON DTO、序列化快照和明确结构的配置对象继续使用普通对象。无原型字典不得直接调用 `hasOwnProperty`、`toString` 等原型方法；需要判断自有键时使用 `Object.prototype.hasOwnProperty.call(dict, key)`。优先使用 `Map` 表达需要频繁增删、迭代或以非字符串为键的注册表和缓存。

## 二、临时数据（temp）操作规范

> **强制约束**：所有临时数据**必须**通过 temp 操作接口（`query_temp` / `set_temp` / `add_temp` / `remove_temp`）进行读写。

1. **禁止直接访问 `temp` 对象：**
   ```typescript
   // ❌ 禁止
   obj.temp["key"] = value;
   let val = obj.temp.key;
   me.temp["bcc"] = 1;

   // ✅ 正确
   obj.set_temp("key", value);
   let val = obj.query_temp("key", 0);
   me.set_temp("bcc", 1);
   ```
   直接访问会绕过过期检查，且不符合序列化规范。

2. **`query_temp` 必须提供默认值：**
   ```typescript
   // ✅ 正确
   const count = me.query_temp("kezhan", 0);
   const flag = me.query_temp("xy_bm", false);

   // ❌ 错误：缺少默认值，可能返回 undefined
   const count = me.query_temp("kezhan");
   ```
   缺少默认值时，key 不存在会返回 `undefined`，导致 `undefined + 1 = NaN` 等运行时错误。

3. **时间单位为毫秒：**
   ```typescript
   // ✅ 正确
   me.set_temp("kezhan", 1, 1000 * 3600 * 24);  // 24 小时
   me.set_temp("buff", 1, 60000);                // 1 分钟

   // ❌ 错误：以为单位是秒
   me.set_temp("kezhan", 1, 86400);  // 实际只有 86.4 秒
   ```

4. **过期机制：** 值以 `{v, e}` 格式存储且 `Date.now() > e` 时，`query_temp` 自动返回默认值并将该键置为 `null`。

5. **`remove_temp` 删除键：** 同时删除临时值及其过期时间记录。

6. **副本入口共享 temp 使用专用方法：** ROOM 的普通 temp 方法仍继承自 ITEM；需要按 AREA owner 定位副本入口时使用：
   - `fb_query_temp(name, me, def?)`
   - `fb_set_temp(name, value, me, time?)`
   - `fb_add_temp(name, value, me, time?)`
   这些方法通过 `AREA.first` 定位入口克隆；从副本克隆调用时优先沿用当前房间 owner，从基础房间调用时使用 `AREA.query_owner(me)`，自动遵循 AREA 的默认队伍 owner 或自定义 owner 规则。

7. **作用范围区分：**
   | 对象 | 作用范围 | 持久化位置 |
   |------|---------|-----------|
   | `me.query_temp()` | 单个玩家 | 该玩家的角色存档 |
   | `WORLD.DATA.query_temp()` | 全服共享 | 数据库 |
   | `this.query_temp()` (ROOM) | 房间自身 | 不持久化 |
   | `this.query_temp()` (NPC) | NPC 自身 | 不持久化 |

## 三、query_prop — 属性加值查询

> `me.query_prop(key)` 永远返回安全的数值，**不需要** `|| 0` 或空值检查。

1. **缺失值保底返回 0，已存储的负数会原样返回：**

   ```typescript
   // ✅ 正确：直接使用，无需防御
   const gj = me.query_prop("gj");
   const fy = me.query_prop("fy");
   const total = gj + fy;

   // ❌ 多余：不需要 || 0 守卫
   const gj = me.query_prop("gj") || 0;  // 多余，query_prop 已经保底 0
   ```

   实现保证：
   - 键名为空或 `"desc"` → 返回 `0`
   - `this.prop` 不存在 → 返回 `0`
   - `this.prop[name]` 为 `undefined` → `|| 0` 兜底返回 `0`

2. **与 `query_temp` 的区别：**

   | 方法 | 默认值 | 空值行为 |
   |------|--------|---------|
   | `me.query_temp(key, def)` | **必须手动提供** | 不提供默认值时可能返回 `undefined` |
   | `me.query_prop(key)` | **缺失时内置为 0** | 已存储的负数会原样返回 |

3. **注意区分 SKILL 上的 `query_prop`：**

   - `me.query_prop(key)` — CHARACTER 方法，查询角色**当前累积**的属性加值，保底 0
   - SKILL 类的 `query_prop(lv, me?)` — 定义该技能**提供**的属性加成，返回 `PropMap`

## 四、类定义与导出规范

1. **必须使用匿名默认导出：**
   ```typescript
   // ✅ 正确
   export default class extends ROOM {
       name = "北大街";
       // ...
   }

   // ✅ 也可以（命名类 + 默认导出）
   export default class WuMiaoRoom extends ROOM { /* ... */ }

   // ❌ 错误：命名导出
   export class MyRoom extends ROOM { /* ... */ }
   ```
   引擎通过 `mod.default` 获取类引用，命名导出不会被识别。

2. **constructor 中必须先调用 `super()`：**
   ```typescript
   // ✅ 正确
   constructor() {
       super();
       this.set_npc("pub/xiaoer");
   }

   // ❌ 错误：super() 之前做了其他操作
   constructor() {
       this.name = "我的房间";
       super();
   }
   ```

## 六、回调中的 this 指向

`add_action` 中传入普通函数时，`this` 默认**不指向类实例**。推荐使用箭头函数或类方法：

```typescript
// ✅ 方式一：箭头函数（推荐）
this.add_action("test", "测试", (me: CHARACTER): void => {
    this.notify("箭头函数中的 this 指向实例！");
});

// ✅ 方式二：类方法（推荐）
this.add_action("test", "测试", this.handleTest);
handleTest(me: CHARACTER): void {
    this.notify("类方法中的 this 指向实例！");
}

// ✅ 方式三：保存引用
const self = this;
this.add_action("test", "测试", function(me: CHARACTER): void {
    self.notify("通过 self 变量访问实例！");
});
```

## 十、技能动作字符串换行约定

> 引擎在 `2026-07-09` 的模板预编译重构中，将换行从 `send_combat` 调用处移入了动作字符串自身。

1. **闪避、招架类动作字符串必须以 `\n` 结尾：**
   ```typescript
   // ✅ 正确
   dodge_actions = [
       "但是$n身子一侧，闪了开去。\n",
       "但是被$p机灵地躲开了。\n",
   ];
   parry_actions = [
       "但是被$p格开了。\n",
   ];
   weapon_vs_weapon_actions = [
       "只听见「锵」一声，被$p用手中$i格开了。\n",
   ];

   // ❌ 错误：缺少 \n
   dodge_actions = [
       "但是$n身子一侧，闪了开去。",  // 缺少换行，消息会连在一起
   ];
   ```

2. **`attack_actions` 和绝招的 `attack_msg` / `damage_msg` / `miss_msg` 不需要手动加 `\n`：**
   - 攻击管线（`do_attack`）在 `send_combat` 之前自动处理换行
   - 只有闪避/招架分支（`par.is_dodged` / `par.is_parried`）现在由动作字符串自身携带换行

3. **适用范围：**
   | 字段 | 需要 `\n`？ |
   |------|------------|
   | `dodge_actions` | ✅ 必须以 `\n` 结尾 |
   | `parry_actions` | ✅ 必须以 `\n` 结尾 |
   | `weapon_vs_weapon_actions` | ✅ 必须以 `\n` 结尾 |
   | `weapon_vs_unarmed_actions` | ✅ 必须以 `\n` 结尾 |
   | `unarmed_vs_weapon_actions` | ✅ 必须以 `\n` 结尾 |
   | `attack_actions` | ❌ 不需要 |
   | `attack_msg`（do_attack 参数） | ❌ 不需要 |
   | `miss_msg`（do_attack 参数） | ❌ 不需要 |
   | `damage_msg`（do_attack 参数） | ❌ 不需要 |
   | `parry_msg`（do_attack 参数） | ❌ 不需要 |
