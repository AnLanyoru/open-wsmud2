# 全局开发约束

> **面向所有 open-wsmud2 开发者。** 以下约束适用于本项目所有实体类型（ROOM、NPC、TASK、USERTASK、AREA、FAMILY、SKILL、OBJ）的编写。各实体编写指南是对以下原则的具体化补充，编写时应同时遵守本文件和各实体编写指南。

---

## 一、类型标注准则

> 编写任何代码时，必须遵循以下类型标注规则。

1. **对象类型属性必须显式标注类型。** 当类属性值为对象字面量（`{...}`）时，必须标注类型：
   ```typescript
   // ✅ 正确
   prop: PropMap = { gj: 10, fy: 5 };
   condition: LearnCondition = {
       skill: { sword: 100 },
       str: 30,
   };
   exits: Record<string, string> = {
       east: "yz/beidajie2",
       west: "yz/wumiao",
   };

   // ❌ 错误：缺少类型标注或使用 as Record<string, ...>
   prop = { gj: 10, fy: 5 };
   exits = { east: "yz/beidajie2" };
   prop = { gj: 10 } as Record<string, unknown>;
   ```
   如果没有现成类型可以使用，询问开发者来创建新的类型。

2. **重写方法（回调钩子）必须显式标注参数类型和返回类型：**
   ```typescript
   // ✅ 正确
   on_enter(me: CHARACTER): void {
       me.notify("欢迎来到" + this.name);
   }
   on_leave(me: CHARACTER, dir: string): boolean | void {
       if (dir === "up") return me.notify_fail("必须先打败守卫。");
   }
   on_heart_beat(dt: number): void {
       for (const item of this.items) { /* ... */ }
   }

   // ❌ 错误：缺少参数类型和返回类型
   on_enter(me) { me.notify("欢迎"); }
   on_leave(me, dir) { return false; }
   ```

3. **`add_action` / `set_item` 的回调函数必须标注参数类型：**
   ```typescript
   // ✅ 正确
   this.add_action("diao", "钓鱼", (me: CHARACTER): void => {
       WORLD.COMMANDS['diaoyu'].enter(me);
   });
   this.add_action("say", "", function(me: CHARACTER, par?: string): void {
       // 处理逻辑
   });

   // ❌ 错误：缺少参数类型
   this.add_action("diao", "钓鱼", (me) => { /* ... */ });
   ```

## 二、临时数据（temp）操作规范

> **强制约束**：所有临时数据**必须**通过 temp 操作接口（`query_temp` / `set_temp` / `add_temp` / `remove_temp`）进行读写。

1. **禁止直接访问 `temp` 对象：**
   ```typescript
   // ❌ 禁止
   obj.temp["key"] = value;
   let val = obj.temp.key;
   me.temp["bcc"] = 1;

   // ✅ 正确
   obj.set_temp("key", value);
   let val = obj.query_temp("key", 0);
   me.set_temp("bcc", 1);
   ```
   直接访问会绕过过期检查，且不符合序列化规范。

2. **`query_temp` 必须提供默认值：**
   ```typescript
   // ✅ 正确
   const count = me.query_temp("kezhan", 0);
   const flag = me.query_temp("xy_bm", false);

   // ❌ 错误：缺少默认值，可能返回 undefined
   const count = me.query_temp("kezhan");
   ```
   缺少默认值时，key 不存在会返回 `undefined`，导致 `undefined + 1 = NaN` 等运行时错误。

3. **时间单位为毫秒：**
   ```typescript
   // ✅ 正确
   me.set_temp("kezhan", 1, 1000 * 3600 * 24);  // 24 小时
   me.set_temp("buff", 1, 60000);                // 1 分钟

   // ❌ 错误：以为单位是秒
   me.set_temp("kezhan", 1, 86400);  // 实际只有 86.4 秒
   ```

4. **过期机制：** 值以 `{v, e}` 格式存储且 `Date.now() > e` 时，`query_temp` 自动返回默认值并将该键置为 `null`。

5. **`remove_temp` 设为 `null`：** 不删除键名，用于 JSON 序列化兼容。

6. **副本房间 temp 方法签名不同：** ROOM 覆写了 ITEM 的 temp 方法，需要额外的 `me` 参数来按玩家隔离副本数据：
   - `query_temp(name, me, def?)` — `me` 是第二个参数
   - `set_temp(name, value, me, time?)` — `me` 是第三个参数
   - `add_temp(name, value, me, time?)` — `me` 是第三个参数

7. **作用范围区分：**
   | 对象 | 作用范围 | 持久化位置 |
   |------|---------|-----------|
   | `me.query_temp()` | 单个玩家 | 该玩家的角色存档 |
   | `WORLD.DATA.query_temp()` | 全服共享 | `data.js` |
   | `this.query_temp()` (ROOM) | 房间自身 | 不持久化 |
   | `this.query_temp()` (NPC) | NPC 自身 | 不持久化 |

## 三、query_prop — 属性加值查询

> `me.query_prop(key)` 永远返回安全的数值，**不需要** `|| 0` 或空值检查。

1. **保底返回 0，不会返回 `undefined` / `NaN` / 负值：**

   ```typescript
   // ✅ 正确：直接使用，无需防御
   const gj = me.query_prop("gj");
   const fy = me.query_prop("fy");
   const total = gj + fy;  // 安全，最小值为 0

   // ❌ 多余：不需要 || 0 守卫
   const gj = me.query_prop("gj") || 0;  // 多余，query_prop 已经保底 0
   ```

   实现保证：
   - 键名为空或 `"desc"` → 返回 `0`
   - `this.prop` 不存在 → 返回 `0`
   - `this.prop[name]` 为 `undefined` → `|| 0` 兜底返回 `0`

2. **与 `query_temp` 的区别：**

   | 方法 | 默认值 | 空值行为 |
   |------|--------|---------|
   | `me.query_temp(key, def)` | **必须手动提供** | 不提供默认值时可能返回 `undefined` |
   | `me.query_prop(key)` | **内置为 0** | 永远返回≥0 的数值 |

3. **注意区分 SKILL 上的 `query_prop`：**

   - `me.query_prop(key)` — CHARACTER 方法，查询角色**当前累积**的属性加值，保底 0
   - SKILL 类的 `query_prop(lv, me?)` — 定义该技能**提供**的属性加成，返回 `PropMap`

## 四、类定义与导出规范

1. **必须使用匿名默认导出：**
   ```typescript
   // ✅ 正确
   export default class extends ROOM {
       name = "北大街";
       // ...
   }

   // ✅ 也可以（命名类 + 默认导出）
   export default class WuMiaoRoom extends ROOM { /* ... */ }

   // ❌ 错误：命名导出
   export class MyRoom extends ROOM { /* ... */ }
   ```
   引擎通过 `mod.default` 获取类引用，命名导出不会被识别。

2. **constructor 中必须先调用 `super()`：**
   ```typescript
   // ✅ 正确
   constructor() {
       super();
       this.set_npc("pub/xiaoer");
   }

   // ❌ 错误：super() 之前做了其他操作
   constructor() {
       this.name = "我的房间";
       super();
   }
   ```

## 五、文件命名与组织规范

1. **文件名使用小写英文字母、数字和下划线。** 不要使用空格或中文字符。
2. **路径不包含文件扩展名。** 编译后的 `.js` 文件由引擎的 `BASE.CREATE` 自动查找。
3. **资源文件按用途分目录：**
   ```
   server/res/
     ├── map/       # 房间（ROOM）
     ├── npc/       # NPC
     ├── obj/       # 物品（OBJ）
     ├── skill/     # 技能（SKILL）
     ├── task/      # 任务（TASK / USERTASK）
     ├── area/      # 区域（AREA）
     ├── family/    # 门派（FAMILY）
     └── cmd/       # 命令（COMMAND）
   ```

4. **导入路径使用相对路径，按文件嵌套深度计算 `../` 数量：**
   ```
   server/res/map/yz/guangchang.ts → import {ROOM} from "../../../core/room/room.js"
   server/res/map/yz/leitai/biwu2.ts → import {ROOM} from "../../../../core/room/room.js"
   ```

## 六、回调中的 this 指向

`add_action` 中传入普通函数时，`this` 默认**不指向类实例**。推荐使用箭头函数或类方法：

```typescript
// ✅ 方式一：箭头函数（推荐）
this.add_action("test", "测试", (me: CHARACTER): void => {
    this.notify("箭头函数中的 this 指向实例！");
});

// ✅ 方式二：类方法（推荐）
this.add_action("test", "测试", this.handleTest);
handleTest(me: CHARACTER): void {
    this.notify("类方法中的 this 指向实例！");
}

// ✅ 方式三：保存引用
const self = this;
this.add_action("test", "测试", function(me: CHARACTER): void {
    self.notify("通过 self 变量访问实例！");
});
```

## 七、禁止修改编译产物

修改代码时只改 `server/` 下的 TypeScript 源文件，不要直接修改 `os/`、`world/` 等编译输出目录中的文件。

## 八、编写实体时的检查清单

在编写任何实体文件前：
0. 完整阅读 `docs/` 下对应的实体编写准则（如有）
1. 按需查阅 `docs/` 下对应的实体编写指南
2. 确认所有对象类型属性已标注类型
3. 确认所有重写方法/回调已标注参数类型和返回类型
4. 确认所有 temp 操作使用 `query_temp`/`set_temp`/`add_temp`/`remove_temp`
5. 确认 `me.query_prop()` 调用没有多余的 `|| 0` 守卫（方法已保底 0）
6. 确认使用匿名默认导出 `export default class extends ...`
7. 确认 constructor 中先调用 `super()`
8. 确认回调中的 `this` 指向正确
9. 确认文件放在正确的资源目录下
10. 全局挂载的函数是挂载在全局无需导入的函数，禁止自己定义
