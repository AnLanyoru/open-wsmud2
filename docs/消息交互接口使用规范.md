# 消息交互接口使用规范

本规范统一说明服务端向客户端发送普通文本、命令按钮和“按钮+说明文本”时的接口选择。编写新功能前，应优先复用下列接口，不要在资源代码中重复拼接客户端协议或 HTML。

## 接口选择

### `send_cmd_and_text`：运行时交互的首选接口

`USER.send_cmd_and_text(...items)` 用于运行时向玩家展示可点击命令，并在按钮旁显示说明文本。每个项目的类型为：

```ts
type CmdAndText = [
    cmd: string,       // 点击后执行的命令
    name: string,      // 按钮标题
    text?: string,     // 按钮对应的说明文本
    br?: boolean,      // 是否换行
    group?: string,    // 客户端分组标题
];
```

示例：

```ts
me.send('<cyn>请选择定向属性：</cyn>');
me.send_cmd_and_text(
    ['spfm hswj 祝融', '祝融', '攻击', true],
    ['spfm hswj 芙蓉', '芙蓉', '命中', true],
);
```

使用要点：

- 接收者必须是 `USER`；资源回调收到更宽泛的 `CHARACTER` 时，先确认 `me.is_player`，再转为 `USER` 调用。
- 命令参数应使用客户端可直接执行的完整命令字符串。
- 说明文本放在第三个元素，不要把说明拼进按钮标题；需要分组时使用第五个元素。
- `br` 适合纵向选项列表；横向短选项可省略。
- 接口会负责生成客户端 `{type:"cmds"}` 数据，调用方不得自行拼接协议 JSON。

### `send_commands`：只有按钮、没有说明文本

当选项只需要按钮标题，不需要每个选项的说明时，可以使用 `USER.send_commands(cmd, name, ...)`。如果按钮需要解释属性、消耗、条件或结果，应改用 `send_cmd_and_text`。

### `span cmd`：仅用于静态房间/场景介绍

`<span cmd="命令">显示文本</span>` 是房间描述、场景介绍等静态 HTML 内容中的链接标记，适用于 `ROOM.desc`、副本奖励说明等随场景一并渲染的内容。例如：

```ts
desc = "石碑旁刻着<span cmd='look3 0 of fb_14'>查看奖励</span>。";
```

禁止在运行时技能提示、状态通知、交互式选择和命令回调中手写 `span cmd`。这些场景必须使用 `send_cmd_and_text` 或 `send_commands`，以保证按钮与文本由客户端协议统一渲染。

## 文本与按钮的组织

1. 先发送简短上下文说明（`send`/`notify`），再发送选项列表。
2. 每个按钮只对应一个明确动作；按钮标题使用面向玩家的名称，说明文本使用属性或结果等补充信息。
3. 选项超过两个时优先逐行显示，避免把长文本塞进按钮标题。
4. 动态名称、物品和数量遵循项目的用户-facing 命名规则：物品优先使用 `color_name` 或 `unit_name(count)`。
5. 命令输入可能包含中文参数时，命令正则必须允许非 ASCII 文本，不能使用只匹配 ASCII 的 `\w` 代替 `\S` 或明确的 Unicode 规则。

## 检查清单

- 这是运行时交互，还是静态房间/场景 HTML？
- 是否需要按钮旁的说明文本？需要则使用 `send_cmd_and_text`。
- 是否错误地手写了 `<span cmd>` 或 `{type:"cmds"}`？
- 每个按钮的命令是否可以直接由玩家执行？
- 是否已处理 NPC/非玩家角色不会调用 `USER` 专用接口？
