# 页面优化记录（含失败经验）

## 最终验证结果（2026-08-03）

第十轮已通过实机验证，本次字号切换造成的文字和分组控件偏移已完善。最终生效的思路是将“文字大小”与“控件定位几何”分离：文字继续响应字号设置，而头部、footer、列表行、切换按钮的中心轴和间距不再被字号成比例拉动。

### 最终保留的改动

1. dialog 头部使用 Flex 对齐标题、图标和关闭按钮；固定头部高度与水平间距，取消 Glyphicons 的全局 `top: 1px` 对 dialog 图标的影响。
2. dialog footer 直系 `.footer-item` 占满 footer 高度并使用 Flex 居中，让文字、选中背景和底部遮罩共用同一几何基准。
3. 技能和背包装备的 1、2、3 分组按钮使用 Flex 居中，宽高、圆角和外边距改为由默认 `0.875rem` 换算的固定 `rem` 值；窄屏覆盖规则同步使用固定几何。
4. 设置页的设置行、标题和选项列表使用 Flex 对齐；行高、内边距、选项尺寸与间距拆分处理，字号变化不再改变选项中心位置。
5. 技能列表和书架行使用 Flex 垂直居中；等级信息改为 `margin-left: auto` 的 Flex 尾部项，取消浮动与文本基线的联动。
6. 背包已装备行使用 Flex 拉伸，装备类型背景块和装备名称独立居中，不再依赖 `inline-block` 基线。
7. 排行 footer 的切换项和描述区使用固定几何基准，窄屏切换项同步使用固定宽度。
8. dialog 工具菜单按钮保留第七轮的两行布局：图标行与文字行分开占位，内部各自居中，不改动原有按钮宽高、`menu_size` 继承和菜单重排步长。
9. 字号、字体、dialog 倍率和菜单倍率变更后，立即通知菜单、背包和排行布局；由各模块自己的单帧调度器合并测量，不再额外等待两帧。

### 未改动的已验证规则

1. 背包货币容器的 Flex 分配、横向滚动、渐隐遮罩和操作按钮溢出逻辑保持不变。
2. dialog 工具按钮的 `2.5em` 宽高、间距、圆角和菜单重排逻辑保持不变。
3. 未使用个别字形 `transform`、`top` 补偿，也没有全局批量将 `px`/`em` 替换为 `rem`。

### 涉及文件

- `web/styles/dialog.css`：dialog 头部、footer、通用切换项和技能分组按钮。
- `web/styles/main.css`：dialog 工具菜单的图标行、文字行和按钮内部布局。
- `web/dialog/packet.js`：背包分组按钮、窄屏覆盖及已装备行。
- `web/dialog/skills.js`：技能列表、等级信息和书架行。
- `web/dialog/setting.js`：设置行与字号/字体/倍率选项。
- `web/dialog/stats.js`：排行 footer 切换项及描述区。
- `web/setting.js`：字体类设置变更后的统一布局通知入口。

### 验证

1. 实机切换字号后，文字、dialog footer 以及技能/背包 1、2、3 分组位置已确认正常。
2. `npm run test:compile` 通过。
3. `node scripts/pack.mjs --binary` 通过。

## 第九轮失败反馈与第十轮尝试（2026-08-03）

### 实际结果

1. 第九轮修复失败：将 dialog 标题、设置项、技能行和 1、2、3 分组按钮改为 Flex 居中后，字号变化仍会发生偏移。
2. 因此“行内基线是唯一原因”的判断不成立，不再继续叠加 Flex、`line-height` 或字形位移补偿。

### 第十轮方法（已实机验证通过）

1. 保留已有的容器居中作为内部对齐，但不再让它承担防止整个控件偏移的任务。
2. 将 dialog 头部、footer、设置行、技能行以及技能/背包的 1、2、3 分组按钮的定位尺寸和间距由 `em` 改为 `rem`。
3. 这些数值按默认 `0.875rem` 字号换算，保持默认档的现有视觉尺寸；切换字号时只改变文字，不再改变控件中心轴和相邻间距。
4. 背包货币已正常，本轮不修改货币容器、滚动和溢出规则。

## 本轮优化提示

1. 字号、字体、dialog 字号和菜单字号变更后，应统一等待新的字体度量生效，再重算菜单布局与 dialog footer 溢出状态。
2. Web 字体异步加载完成时需要再刷新一次，避免先用旧字体度量排版，导致文字短暂或持续偏下。
3. 已装备物品左侧的装备类型不应依赖 `inline-block` 的文本基线；装备行与类型块使用 Flex 拉伸和居中，避免底部留出基线空隙。

## 失败记录维护约定

后续每次用户明确反馈“失败”时，继续将当次现象、原因、已尝试方法和下次约束追加到本文档，不覆盖既有记录。

## 背景

尝试将现有页面从固定尺寸改为同时适配屏幕空间和字体大小。实际结果没有解决核心布局问题，除 dialog 底部分区栏的白色遮罩对齐有所改善外，其余页面只是局部缓解，部分场景反而出现更严重的挤压、滚动嵌套和空间分配异常。

相关失败改动已经回退，只保留底部分区栏的最小修复。

## 唯一有效的改动

底部分区栏的问题不是整个页面缺少流式布局，而是字号或字体变化后，分区栏仍沿用变化前的宽度测量，同时分区项没有占满 footer 高度。

保留的处理方式：

1. 修改主字号、字体或 dialog 字号后，仅重新计算背包和排行 footer 的溢出状态。
2. 排行 footer 的分区项使用完整高度的 Flex 居中，使文字、选中背景和下方白色遮罩使用同一几何基准。
3. 不因此修改 dialog、消息区或功能页的整体高度分配。

## 失败方法

### 用外层滚动掩盖内部固定尺寸

给 dialog 外层增加 `max-height`、`overflow` 和 Flex 收缩，只能保证内容勉强可访问。功能页内部仍然保留固定高度和固定双栏结构，因此会形成嵌套滚动，不能算真正的自适应布局。

### 批量把固定高度替换为 `height: 100%`

`height: 100%` 依赖父级存在明确高度。当前 dialog 的高度链路由内容、消息区、底栏和浮动菜单共同决定，直接批量替换会让不同页面争夺空间，导致列表过高、过低或滚动区域失效。

### 一次性放宽桌面页面宽度

将原有 768px 内容宽度直接扩展到更大的流式宽度，会改变信息密度和阅读距离。内部组件没有同步建立列宽规则时，宽屏只会放大空白和错位。

### 全局替换 `px` 为 `rem` 或 `em`

尺寸单位转换不等于响应式设计。边框、图标、命中区域、内容列宽和断点具有不同语义，机械替换会使字体缩放同时放大不该变化的几何尺寸。

### 同时修改过多布局层级

同时调整 viewport、body、主容器、dialog、功能页和菜单重排后，无法从实际结果判断是哪一层造成回归，也缺少可验证的回退边界。

## 后续约束

1. 每次只选择一个真实页面和一个明确问题，不再全局批量修改。
2. 先记录该页面在窄屏、宽屏、小字体和大字体下的实际 DOM 尺寸与滚动容器。
3. 明确唯一的高度所有者，避免父子两层同时滚动。
4. 双栏转单栏必须按页面交互单独设计，不能用全局 CSS 强制堆叠。
5. 固定尺寸应先区分为视觉常量、字体相关尺寸、内容尺寸和可用空间尺寸，再决定是否修改。
6. 每完成一个页面就进行真实浏览器对比；没有截图或可复现尺寸时，不宣称问题已经解决。
7. 保留小而独立的修复，发现整体方案回归时立即回退，不让有效改动与实验性改动绑定。

## 推荐的后续顺序

建议依次处理背包、设置、江湖、排行等页面。每个页面单独建立响应式规则和验收尺寸，确认稳定后再复用经过验证的布局模式。
