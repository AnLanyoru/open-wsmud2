# 前端扩展模块修复记录

## 背景

本轮修改主要整理 `web/dialog/extend.js` 及设置页相关的扩展功能，集中处理以下问题：

- 扩展配置导入、编辑、排序和删除后的状态容易残留。
- 条件参数中的等号判断会意外修改原数据。
- 扩展教程内容不完整，帮助入口和展示方式不统一。
- 从扩展编辑页切换到其他设置页后，页签和命令目标可能错位。
- 操作录制依赖已关闭的编辑 DOM，停止录制后无法稳定恢复和保存。
- 扩展操作按钮缺少统一的局部样式。

涉及文件：

- `web/dialog/extend.js`
- `web/dialog/setting.js`
- `web/dialog/base.js`
- `web/script.js`

## 第一阶段：扩展配置与条件处理

首先整理了扩展配置的初始化和列表维护：

- 读取本地配置和导入 JSON 时统一经过数组校验与浅拷贝。
- 导入文件必须包含 `items` 数组，避免错误数据覆盖现有配置。
- 列表刷新时清理旧的选中项及浮动操作按钮，防止 DOM 索引残留。
- 删除扩展改用标准 `splice`，不再依赖自定义的 `Array.prototype.Remove`。
- 停止录制时对尚未创建的编辑节点增加保护。

条件处理同时修复了以下问题：

- 将内部拼写错误的 `condtion` 整理为 `condition`，保留旧名称作为兼容入口。
- 参数语法增加 `=` 运算符识别。
- 原 `=` 实现使用赋值表达式，会修改被检查对象；现改为严格比较。
- 数字比较统一显式使用十进制解析。

## 第二阶段：帮助文档与帮助窗口

原帮助内容分为三个可点击列表，内容不完整，且存在“持续增加”等占位文字。本轮补全了：

- `#wait`、`#msg`、`#menu`、`#action`、`#pfm` 等命令。
- `@me`、`@dir`、`@npc`、`@item`、`@pack`、`@goods`、`@id`、`@obj`、`@input`、`@mat`、`@data`、`@master`、`@dc` 等变量。
- 多命令分号语法、对象条件语法、比较运算符和文本正则示例。

帮助展示改为一个统一窗口：

- 复用现有 `float-dialog-unified`、遮罩、标题栏和内容行样式。
- 命令、变量、条件参数在同一个可滚动窗口中展示。
- 支持关闭按钮、点击遮罩关闭和底部渐隐提示。
- 离开扩展页面时自动移除帮助窗口。
- 没有新增全局基础样式。

帮助按钮曾出现无法点击的问题，原因有两处：

1. `ecmd="show_help"` 会被旧命令分发器按下划线拆成 `show` 和 `help`，但对应方法已经不存在。
2. `extend.js` 使用 `SCRIPT.helper` 时没有显式导入 `SCRIPT`，打开窗口会产生运行时错误。

最终将命令改为单段 `ecmd="help"`，对应 `cmd_help`，并显式导入 `SCRIPT`。

## 第三阶段：设置页切换状态错乱

扩展新增或编辑状态下点击其他设置页时，扩展子页的 `hide()` 会返回 `false`，表示本次操作只退出编辑状态，不应真正离开扩展页。

旧实现的问题是：在询问子页能否离开之前，就已经修改了 `selectitem` 并移除了当前节点。即使子页拒绝切换，页签、内容节点和命令分发目标也已经部分更新，导致返回扩展页后“添加扩展”等按钮失效。

最终引入事务式页脚切换：

1. 当前子页先执行 `hide()`，确认是否允许离开。
2. 返回 `false` 时，不修改当前内容节点、子页引用和选中页签。
3. 允许离开后，再一次性提交新节点、新子页和页签状态。
4. 导入、导出、添加等动作按钮只执行命令，不会被误设为当前页签。

公共对话框通过 `transactionalFooter` 选择是否启用此模式。设置页已启用，其他依赖旧页脚行为的页面保持原逻辑，避免影响背包整理等特殊交互。

## 第四阶段：录制流程重构

### 失败的中间方案

录制后保存失败时，曾错误地把问题归因于编辑项 `sid` 丢失，并尝试在停止录制时补写或重置索引。这个方案不符合录制功能的职责：录制只应替换指令内容，不应决定当前是在新增还是编辑扩展。

该处理已经撤销。保存阶段仍保留非法索引保护，作用仅限于防止异常数据导致运行时错误。

### 最终模型

录制流程改为“闭包编辑快照，停止后重建”：

1. 点击开始录制时，从编辑界面读取全部字段及原有新增/编辑上下文。
2. 使用闭包保存该快照，随后关闭对话框并开始记录操作。
3. 录制期间不再读取或修改原编辑 DOM。
4. 点击停止时，用录制得到的命令串替换闭包快照中的 `content` 字段。
5. 重新初始化扩展编辑 DOM 和事件处理器。
6. 按顺序恢复扩展类型、适用范围、名称、条件参数和新指令内容。

为支持安全重建，扩展编辑区事件改用 `.extend` 命名空间。每次初始化先移除该命名空间下的旧事件，再重新绑定，避免重建后一次点击触发多次处理。

录制流程应长期保持以下约束：

- 录制只负责产生并替换 `content`。
- 新增或编辑上下文由开始录制前的编辑快照决定。
- 停止录制必须从快照重建界面，不能依赖隐藏前的 DOM 仍然存在。
- 即使没有录制到命令，也应恢复编辑界面，由用户决定是否继续填写。

## 第五阶段：按钮样式

扩展模块的编辑、上移、下移、移除、帮助和保存按钮统一使用项目已有的主题变量：

- `--btn-border`
- `--btn-color`
- `--btn-bg`
- `--dialog-highlight`

调整仅作用于扩展模块，增加边框、圆角、内边距、字体继承和按压反馈。“保存”使用高亮色表达主操作。扩展帮助按钮仍位于原菜单区域，并保留原有伸缩占位区，确保保存按钮位置不发生变化。

## 回归检查清单

后续修改扩展模块时至少检查以下流程：

1. 添加扩展，填写字段后直接保存。
2. 编辑已有扩展并保存，确认启用状态不丢失。
3. 添加或编辑时开始录制，执行多条命令后停止并保存。
4. 录制停止后确认名称、类型、适用范围和条件参数保持不变，只有指令内容被替换。
5. 在扩展编辑状态点击其他设置页，第一次只退出编辑态，第二次正常切换。
6. 切换回扩展页后测试添加、导入、导出、编辑、排序和删除。
7. 打开和关闭扩展帮助窗口，确认遮罩、滚动和关闭按钮正常。
8. 导入合法及非法 JSON 文件，确认非法文件不会覆盖当前配置。
9. 验证 `=、!=、>、<、>=、<=` 条件不会修改原对象数据。
10. 执行 `npx vite build`，确认前端构建通过。


构建已通过。
